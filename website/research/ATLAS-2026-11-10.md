# Interactive atlas and trip styles

## Data contract

- Authored destinations remain in the existing catalog sources. `compile_release.py` creates the 798 trip profiles. The three original broad profiles remain in `src/data.json`.
- `src/trip-types.json` still owns the 41 named local classics. Its slugs, `tripTypeIds`, planner presets, saved-plan field, shared snapshot, inquiry and export retain their identities.
- `src/trip-styles.json` owns the 16 discovery styles. `scripts/trip_styles.py` derives `tripStyleIds` from habitat, method, access, narrow title/summary fields and explicit local-classic membership. A destination can match several styles.
- `src/atlas-locations.json` owns the map reference coordinates. Each record identifies the source feature, query, source URL, precision and display label. Coordinates identify an approximate named feature or region. They do not identify a launch site, available trip or safe route.
- `world_extension.py` places the style and coordinate fields on each planner destination before any catalog is written. `continental_extension.py` preserves style membership on its compact trip records.
- `compiled-data.json` and `dist/assets/data.js` retain the same destination identity and location. `scripts/interactive_atlas.py` exports a compact, content-hashed map catalog from those records.
- The home map, full atlas, live filters, result counts, pin cards and accessible result list consume that one map catalog. Style pages use the same compiled memberships.
- Each style page links all matches and its local classics. Destination pages and local classics link back to their styles. `/trips/` has a Local classics row. The local-classic directory is `/local-classics/`; all 41 detail URLs stay under `/trip-types/`.
- The page registry drives canonical tags, breadcrumbs, schema and the sitemap. No existing named URL moves. Existing redirect rules remain intact.

## Evidence boundaries

The supplied task said all coordinates existed in `compiled-data.json`. The latest starting commit contained coordinate strings for only three original profiles. The other 798 records had none. The release adds a source register rather than invent positions from the destination order or scatter pins randomly.

Location lookups form a one-time, single-thread, cached research task. Requests remain below one per second. Normal builds and live visitors make no requests to a geocoding service. OpenStreetMap attribution and the shareable location register remain public.

The Natural Earth 110m base map is self-hosted. D3 and TopoJSON code is bundled and self-hosted. The source, locked dependencies and license notices remain in the repository. No API key or paid tile service is used.

Candidate species can match a search, but a research-pending card does not present them as verified fish. Month filters use only existing `seasonWindows`. Missing months do not imply no fishing. Three-month windows use explicit month names, so they do not impose northern-hemisphere seasons on the whole world.

The trip images come from the existing responsive trip-image manifest. Other cards retain their current scene fallback. All scene images remain identified as illustrations.

## Interaction and access

The loader starts the map only near the viewport or on focus. It handles a failed load with a retry and a static destination list. The home page includes a short static list preview. The full atlas includes all 801 destination links without JavaScript.

The map has clusters, wheel and pinch zoom, drag and arrow-key pan, zoom buttons, reset, region fly-to controls and a paginated accessible list. Coincident points expose a choice of trips. Reduced motion removes the decorative route introduction and animated camera changes.

The mobile filter button saves map space. It exposes the same water, style, month and search fields as desktop. A change of viewport retains the map and current filter state.

## Build

Normal site build: `python3 scripts/build_vercel.py`.

Map bundle rebuild, only after a map source change: `npm --prefix client ci && npm --prefix client run build`.

The bundle is committed. Vercel does not need an npm install to build the site.

## Location audit outcome

All 801 records have a geographic reference. The source register contains 602 place-area points, 192 regional points and seven country-only references. The latter remain explicit in the card and atlas note. The existing catalog does not establish an exact departure for those broad records.

OpenStreetMap supplies 786 records. GeoNames supplies nine. The original catalog supplies three. USGS, Wikidata and a published Pluma River field study supply one each. The register identifies every source.

The Papatura operator metadata conflicts with the geographic island record. The map uses the island reference from GeoNames, with Tourism Solomons support for the island name. It does not claim the retreat or river coordinates.
